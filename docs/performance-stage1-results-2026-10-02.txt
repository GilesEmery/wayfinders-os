Implementation
- Fresh shared course authorization retains identity, password gate, access,
  explicit cohort selection, canonical version pinning and requirement bypass.
- Mutation loaders retain authorized full curriculum and response contracts while
  omitting progress display reads, themes, appearance assets, signing and companion.
  Trusted server-only context is reused by progress helpers within the operation.
  PIS, Start Something, numeric assessments and generic response saves use it.
- Visible assessment cards receive batched metadata and canonical/embedded status
  derived from the already-authorized runtime. Preview reads no participant status.
- One targeted companion endpoint replaces 12-second router.refresh polling.
  Every read authenticates and checks password, pinning, delivery visibility,
  active cohort membership, module scope, audience and visibility. It does not
  provision overrides or load blocks, response data, resources or signed files.
  Hidden pages pause polling; in-flight polls do not overlap; unmount aborts them.
  Access denial/password redirect clears local live state. Transient failures
  retain the last successful window. Message IDs reconcile deletions, timestamp
  cursors limit returned bodies, and missing IDs trigger a fresh window repair.
  Call configuration/session state updates locally; live calls display Call live.
- Chat reads take the newest 200 messages and reverse them for display, with an ID
  tie-break. This remains a bounded combined window; older-message pagination is
  deferred. Chat send/delete actions retain their existing authorization and
  explicit revalidation behavior.
- Resource metadata remains one deduplicated lookup. Display signing batches by
  bucket; downloads sign individually in parallel to preserve original filenames.
  Private 900-second expiry is unchanged. No cross-request asset/auth cache exists.
- WAYFINDERS_PERFORMANCE=1 enables JSON diagnostics with fixed operation labels,
  total elapsed milliseconds and HTTP request counts/summed duration grouped as
  databaseHttp, storageHttp, authHttp and otherHttp. URLs, IDs, headers, tokens,
  answers and bodies are never included. Parent scopes include child requests;
  overlapping/nested spans must not be summed as independent requests.

signing and expiry behavior. Tests use mocks rather than a live isolated database.
