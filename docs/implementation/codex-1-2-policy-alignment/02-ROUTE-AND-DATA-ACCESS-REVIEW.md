**Verified from local code:** historical completion uses the completion JSON projection rather than whole archived answers (`lib/admin/wayfinders/journey.ts:22`). The publication migration constructs completion status/date/version metadata separately from removed response snapshots (`supabase/migrations/20260917211108_atomic_publish_forward.sql:301`, `:354`). Operational CSV selects only dates/status and identifiers from resulting records, with no raw snapshot serialization (`lib/admin/wayfinders/operational-export.ts:17`).

**Inference:** exact cohort progress cannot safely be inferred from a canonical participant/course status while multiple active cohorts exist. Membership proves a person belongs to a cohort; it does not prove all stored course progress happened there. Existing enrollment `cohort_id`/`offering_id` explicitly remain compatibility pointers (`supabase/migrations/20260918112528_canonical_enrollment_multiple_cohort_contexts.sql:22`, `:29`, `:32`). A future context-attributed progress relation is needed; no SQL design was executed.

**Verified from local code:** alternate roster/contact domains remain: admin users/Hub/cohort CRM, learner search and Companion author/member lists. Their global admin or resolved delivery gates were not replaced by directory membership. Ordinary creator membership gets no new access. The open-Hub connection helper still ignores preexisting membership/preference read errors (`lib/platform/hub-membership.ts:12`, `:18`); it was inventoried, not executed or rewritten. No blanket “all paths secure” claim is made.
