## Separation rules and implementation status

**Verified from local code; verified by isolated test:** operational CSV is a separate function, never a mode passed into the private body exporter. Its explicit field list ignores extra `response_data`, `result_data`, `email`, and `artifact_snapshot` properties in test records (`lib/admin/wayfinders/operational-export.ts:17`; `scripts/security/codex1-2.test.mjs:84`). The default export URL remains owner-only. Missing admin is a 403; database/audit uncertainty returns an unavailable error through the route, with no-store headers.

**Verified from local code; verified by isolated test:** directory membership does not imply contact access, cohort authority or sharing. Contact proof reuses a persisted exact-Hub explicit `wayfinder.view` allow override; inherited role permissions and Super Admin alone do not satisfy it. This is a restrictive compatibility rule for an existing permission key, not a new catalog permission or granted override (`lib/platform/hub-directory.ts:34`; `supabase/migrations/20260923163326_authority_entitlements_foundation.sql:56`; `scripts/security/codex1-2.test.mjs:66`). No override row was created or modified.

**Verified from local code; inference:** course ownership does not imply publication/enrollment/reporting. Legacy course helpers have a broad administrative path but ordinary creator entry remains denied; no creator was elevated to global admin (`lib/platform/authorization.ts:73`, `:77`; `lib/experiences/admin/version-release.ts:10`; `lib/experiences/admin/enrollment-mutations.ts:9`). A later scoped entry implementation must enforce separate explicit permissions; source helpers alone are not a completed creator flow.

**Verified from local code:** response raw/result visibility is independent, but the active nonowner adapter provides neither durable scope nor consent. All current nonowner response levels remain denied; owner access survives (`lib/platform/response-sharing-policy.ts:21`; `lib/platform/response-library.ts:249`). The 27 level/role cases from CODEX 1.1 remain in the retained test suite (`scripts/security/codex1-1.test.mjs:24`). Approved audiences are not working shared-body features.

**Inference:** prior CODEX 1.1 recommendations for implicit operational-admin directory exceptions and a proposed aggregate cell threshold are superseded by the current approval: directory only exact members/leaders, separate contacts, no new small-group analytics or threshold. Historical reports were preserved, not edited. Closed-Hub description visibility remains the specifically excluded policy question.

**Requires live verification:** persisted role/override semantics, exact-count receipts, recipient withdrawal/revocation timing, deployed RLS and browser payloads must be checked using synthetic staging records before release. None of these is inferred from passing mocks.
