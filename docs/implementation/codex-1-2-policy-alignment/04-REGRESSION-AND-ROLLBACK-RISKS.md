## Security regression and rollback contract

**Inference:** exact counts add server count work and can deny large/truncated catalog/roster reads that previously appeared successful. This is an intended availability tradeoff against missing denies, not performance optimization. If counts are unknown, stop; never remove the checks to restore access. Establish deployed count support/row limits before release (`lib/platform/effective-access.ts:36`; `lib/platform/hub-directory.ts:22`).

**Inference:** rollback should disable affected feature entry points and retain owner-only body protection. Restore only a reviewed safe application version; reverting blindly to pre-CODEX 1 can reintroduce private-answer access. No schema rollback is needed for this patch because no schemas/migrations changed.

**Inference:** rollback cannot undo participant writes already accepted, in-flight server mutations, publication/activation, downloaded CSV, copied text or already-issued signed URLs. It cannot revoke existing database grants. Any data correction, grant change, migration or published-content repair requires separately authorized action. Stop on unauthorized reads, cross-identity writes, missing acknowledged saves, broken essential operational paths or unconfirmed cleanup/publication, preserve non-sensitive evidence, and verify server state before retry.
